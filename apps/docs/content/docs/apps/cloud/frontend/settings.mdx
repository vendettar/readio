## 1. Scope

- Route: `/settings`
- Main interface: `apps/cloud-ui/src/routeComponents/SettingsPage.tsx`

## 2. Current Cloud Role

Settings still owns:

- language switching
- content region
- browser-local maintenance actions
- library export/import flows where still present
- storage disclosure for browser-local persistence limits
- user-owned provider credential entry and verification surfaces where the current UI exposes them

## 3. Cloud Boundary

Cloud Settings should document current Cloud-specific ownership and must not reintroduce legacy proxy configuration blocks that were intentionally removed from the Cloud contract.

## 4. Credentials and Export Boundary

- Provider credentials are not general settings. They must use the browser-local credentials repository or transient in-memory values defined by the current runtime contract.
- Settings export/import must not include provider credentials.
- Clearing all local data must include credentials and must guard against stale async writes recreating cleared values.
- Runtime defaults may prefill visible provider/model choices, but they must not silently persist API keys.
