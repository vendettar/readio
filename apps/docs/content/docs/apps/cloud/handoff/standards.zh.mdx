---
title: 开发标准
---

## 1. 共享前端标准

Cloud 前端继续沿用主要的 Cloud 前端工程规则：

- tokenized layout，避免任意 UI 漂移
- 原子化 Zustand selector
- 显式异步取消
- 长列表场景的 memoized 渲染
- UI 不得绕过既定持久化边界直接写 DB

## 2. 异步与状态完整性

异步流程必须同时维护取消语义和 ownership 边界。

- 底层 API 支持时，`AbortSignal` 必须传递到真实的网络、stream、storage 或 parser 操作。
- 仍然需要 stale-result 检查，但它不能替代对昂贵任务的取消。
- request ID 与 latest-wins 顺序必须按 domain/key 隔离。一次 search 请求不得取消或压制无关的 episode、transcript、playback 或 settings 请求。
- 不同实体的并发加载必须能独立取消。
- 异步流程测试应覆盖 active path、aborted path、stale-result path；如果功能会产生重叠请求，还应覆盖至少一个跨 key 并发场景。

## 3. 导航契约

- 标题/封面仍然是 discovery / library 行项目的主要导航发射点
- 单集行继续保持“直接播放”和“详情跳转”分离
- 规范化播客/单集路由必须基于当前 Cloud discovery identity contract 生成

## 4. 持久化边界

- 浏览器本地写入必须继续经过 store action / repository helper
- 组件应复用共享 DB/domain 类型，而不是临时拼接本地数据结构

## 5. 资源生命周期

浏览器拥有的资源必须有明确释放路径。

- media/source owner 切换 source、unmount 或失去 blob ownership 时，必须 revoke object URL。
- 长生命周期缓存清理前，必须区分仍被引用的记录和真正 orphaned 的记录。
- cleanup job 必须有边界，且不得删除仍可从 active playback、sessions、downloads、transcripts 或 library state 访问到的记录。

## 6. UI 与交互治理

- 优先复用现有 primitives 与 semantic tokens，再考虑新增 UI 结构。
- overlay、focus、keyboard、escape 与 layering 行为属于组件契约，不只是视觉润色。
- 等价 workflow 的 loading、empty、error、disabled 与 retry 状态应保持一致。
- 修复行为时不要顺手重设计界面；视觉变化需要和功能变化一样有 owner 与验证。

## 7. 无障碍基线

Cloud 前端继续保持这些既定基线：

- command palette 键盘交互
- transcript 选区/菜单语义
- player control ARIA
- overlay 的确定性关闭/escape 行为

## 8. 审查与验证基线

实现审查默认聚焦 changed surface，并包含：

- 被审查的 diff 或 commit range
- 正确性与回归风险
- 缺失测试或尚未验证的边界条件
- ownership/path drift，尤其是旧 lite 路径或过期 Cloud 契约

问题记录应包含 severity、evidence、impact、fix direction 与 verification。只有当变更跨越架构、安全或性能边界时，才升级为更宽范围的专项审查。

## 9. Debug 观测性标准 (Debug Observability)

- **拒绝静默跳过 (No Silent Skips)**：任何丢弃数据或跳过循环的操作（例如映射循环中的 `continue`），必须在此之前调用 `slog.DebugContext(ctx, ...)` 明确记录跳过原因和条目标识符。严禁缺失如 `link` 等字段时无日志直接抛弃。
- **上游交互透明化 (Upstream Transparency)**：所有向第三方发起的 HTTP 请求，必须在 DEBUG 级别使用 `slog.DebugContext(ctx, ...)` 记录外发请求 URL、响应状态码、响应体大小以及解析出的有效条目数（`count`）。
- **统一键名 (Standardized Keys)**：日志记录强制使用标准键名：`error`, `guid`, `itunes_id`, `latency_ms`, `count`。
