# 当前决策

这些是 Readio Cloud 原型的当前项目决策。

## D001 — Cloud 是当前产品表面

`apps/cloud-ui` 与 `apps/cloud-api` 是当前 Web 产品。文档必须把这套前后端拆分实现描述为 Cloud 架构。

## D002 — 前端/后端所有权必须明确

`apps/cloud-ui` 拥有 browser-local 播放、下载、文件、transcript、收藏、历史、订阅、设置与阅读 UI。`apps/cloud-api` 拥有 runtime config、discovery relay、PodcastIndex-backed routes、ASR relay、media fallback、SQLite 与 observability。

## D003 — Cloud discovery 由后端拥有

可见 discovery 流量经由 `apps/cloud-api`：search、top charts、Editor's Picks batch lookup、podcast lookup，以及 PodcastIndex episode-list/detail surface。拆分生产部署中，前端通过配置的 API base URL 使用这些路由。

## D004 — 单集页面使用 SQLite retained snapshot

Podcast 单集列表页面渲染使用后端 SQLite retained snapshot。snapshot 存在后，分页读取必须是 DB-only。直接单集详情按 podcast identity + episode GUID 查找，不触发上游 freshness 检查。

## D005 — Media fallback 必须窄且透传

远程媒体默认 browser-direct。后端 fallback 只服务已批准的 failure classes，必须 non-caching，并保留 validation、request bounds、rate limit 与 structured logging。

## D006 — ASR transcription 使用后端 relay

Cloud provider transcription submission 走 `apps/cloud-api`。Provider credentials 仍由用户拥有，并由浏览器随请求提供；服务端持久化这些凭证不属于 Cloud 契约。

## D007 — Runtime config 必须 allowlist

浏览器可见 runtime config 来自显式 allowlist，只包含 browser-safe 字段。服务端私有配置必须留在服务端。

## D008 — Browser-local 数据不是服务端同步

除非某个功能明确声明 backend persistence contract，否则 browser-local library data 不能从后端恢复。后端 shared transcript asset 只是窄范围的 podcast artifact 功能，不代表通用用户库服务端存储。

## D009 — Observability 由应用有界拥有

`apps/cloud-api` 拥有请求指标、tracing、应用可见的 host/process signals、admin summary endpoints 与有界 log shipping。Admin surface 必须有应用与基础设施保护。

## D010 — 文档只保留最终状态

项目文档必须简洁、对齐代码、只描述当前最终契约。实现迁移历史留在 git history，不复制到活跃文档。
