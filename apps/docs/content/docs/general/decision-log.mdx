# Decision Log

This log records only current effective decisions for the prototype. Superseded prototype steps are intentionally omitted.

## D001 — Cloud is the active product surface

`apps/cloud-ui` and `apps/cloud-api` are the active web product. Documentation must describe the current split frontend/backend implementation and must not present old early frontend-only bootstrap phases as active architecture.

## D002 — Frontend/backend ownership is explicit

`apps/cloud-ui` owns browser-local playback, downloads, files, transcripts, favorites, history, subscriptions, settings, and reading UI. `apps/cloud-api` owns runtime config, discovery relay, PodcastIndex-backed routes, ASR relay, media fallback, SQLite, and observability.

## D003 — Discovery is backend-owned for Cloud

Visible discovery flows route through `apps/cloud-api`: search, top charts, Editor's Picks batch lookup, podcast lookup, and PodcastIndex episode-list/detail surfaces. Frontend code consumes these routes through the configured API base URL in split production deployments.

## D004 — Episode pages use retained SQLite snapshots

Podcast episode-list page rendering uses backend SQLite retained snapshots. Once a snapshot exists, pagination is DB-only. Direct episode detail lookup is keyed by podcast identity plus episode GUID and does not trigger upstream freshness checks.

## D005 — Media fallback is narrow and pass-through

Remote media remains browser-direct first. Backend fallback exists only for approved failure classes, stays non-caching, and keeps validation, bounded requests, rate limits, and structured logging.

## D006 — ASR transcription uses a backend relay

Cloud provider transcription submission goes through `apps/cloud-api` where configured. Provider credentials remain user-owned and browser-supplied per request; server-side credential persistence is not part of the current contract.

## D007 — Runtime config is allowlisted

Browser-visible runtime config comes from explicit allowlists and contains only browser-safe fields. Server-side private config stays server-side.

## D008 — Browser-local data is not server sync

Browser-local library data is not recoverable from the backend unless a feature explicitly defines a backend persistence contract. Backend shared transcript assets are a narrow podcast artifact feature and do not imply generic user library storage.

## D009 — Observability is app-owned and bounded

`apps/cloud-api` owns request metrics, tracing, host/process signals available inside the app, admin summary endpoints, and bounded log shipping. Admin surfaces require application and infrastructure protection.

## D010 — Docs are final-state only

Project docs must be concise, code-aligned, and final-state oriented. Use git history for superseded implementation steps instead of copying transition narratives into active documentation.
