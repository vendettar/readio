# Monorepo 策略

Readio 是带 Go 后端的 Cloud Web App，并保留一个占位 native app surface。本文档定义各 workspace app 的当前角色。

## 1. 应用概览

| 应用 | 路径 | 类型 | 角色 |
|---|---|---|---|
| **Cloud UI** | `apps/cloud-ui` | SPA/Web App | 承载播放、discovery、library、files 与 settings 的主要前端表面。 |
| **Cloud API** | `apps/cloud-api` | Go 后端 | 后端 API 路由、同源 relay、proxy/fallback 路由，以及 SQLite 启动。 |
| **Native** | `apps/native` | Mobile | 占位 native app surface；实现前不记录产品契约。 |

---

## 2. Cloud 策略 (后端)

### 前后端拆分
- **后端**: `apps/cloud-api` 是 Go `net/http` 后端。它提供 API 路由、同源 backend relay，并可在共置部署中提供构建后的 `apps/cloud-ui/dist`。
- **前端**: `apps/cloud-ui` 是活跃 Web 前端。
- **共享包**: 只有当共享 presentation 或 domain package 真实存在于 workspace 后，才记录为契约。

### 技术栈
- **框架**: Go `net/http`。
- **数据库**: SQLite。

---

## 3. Native 策略 (包装器)

**角色**: 访问 PWA 无法触及的系统 API。

### 技术栈
- **框架**: 当前没有活跃 native runtime contract。
- **共享代码**: 不要假设不存在的共享包。

---

## 4. 共享包 (`packages/`)

现状文档只应描述当前真实存在、真实被使用的共享包。

- 不要继续把 `packages/core` 视为现行契约，除非该包重新存在并被工作区使用。
- 只有在共享代码真正抽取出来之后，才在此处声明新的共享包拓扑。
 
---
 
## 5. 引擎策略 (Engine Policy)

为了防止架构漂移和“在我的机器上能运行”这类 Bug，整个 monorepo 严格强制执行工具版本：

- **运行时 (Runtime)**: Node.js `>=20.0.0` (LTS 基准)。
- **包管理器 (Manager)**: pnpm `>=10.28.0` (Lockfile 版本稳定性)。
- **强制措施**: 在根目录 `.npmrc` 中强制设置 `engine-strict=true`。

---

## 6. 缓存策略 (Turborepo)

为了最大化构建性能并防止过时的输出：

- **全局依赖**: `.npmrc` 和 `pnpm-workspace.yaml` 变更时会使所有缓存失效。
- **构建输入**: 源文件 (`src/**`)、配置文件 (`vite.config.ts`、`tsconfig.json`)，排除测试文件。
- **构建输出**: `dist/**`、`.next/**`、`stats.html`。
- **依赖传播**: `^build` 确保上游包先重新构建。
- **不缓存任务**: `dev` 和 `format` 永远不缓存。

**验证**: 运行 `pnpm build` 两次。第二次应显示 `>>> FULL TURBO`。
