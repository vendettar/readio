# 技术路线图

本路线图记录当前原型基线与近期维护工作。

## 当前基线

- 活跃前端：`apps/cloud-ui`，使用 React、Vite、TanStack Router/Query、Zustand、Dexie、i18n，并包含已测试的 UI flows。
- 活跃后端：`apps/cloud-api`，使用 Go `net/http`、SQLite startup/migrations、discovery relay、ASR relay、media fallback、transcript asset metadata 与 observability。
- 活跃文档：`apps/docs/content/docs`，尤其是 Cloud handoff 与 frontend contract 文档。

## 已完成基线契约

- Cloud 前端/后端拆分，并支持生产拆分部署。
- 后端拥有 search、top charts、Editor's Picks、podcast lookup 与 PodcastIndex episode list/detail discovery routes。
- PodcastIndex 单集页面渲染由 SQLite retained snapshot 拥有。
- 媒体默认 browser-direct，后端只提供窄范围 pass-through fallback。
- Cloud ASR relay 负责 provider transcription，同时 provider credentials 仍由浏览器随请求提供。
- Browser-safe runtime config allowlist。
- 应用拥有 observability、metrics、tracing、有界 log shipping 与受保护的 admin summaries。

## 近期维护优先级

1. discovery、ASR、media fallback、SQLite、runtime config 或 browser-local persistence 发生变化时，同步更新文档。
2. 继续拆分大型前端 orchestration components，但不得改变用户可见行为。
3. 保持仓库验证严格：build、lint、typecheck、unit tests、e2e coverage、Go tests 与 docs consistency checks。
4. 通过 validation、request bounds、rate limits 与 structured logging 保持 public fallback 和 ASR surface 的抗滥用能力。

## 未来方向

- 用户账号与服务端同步。
- 多用户 SaaS 部署与认证。
- Native mobile app。
- 当前前后端边界稳定后，再考虑更广泛的共享包。

未来项只有在代码、测试与文档一致后才进入活跃契约。
